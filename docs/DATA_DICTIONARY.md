# Data dictionary

## Directory layout

| Path | Contents | In git |
|---|---|---|
| `data/raw/permits/county/` | BPS county files, gzip (deterministic), exactly as served | yes |
| `data/raw/permits/state/` | BPS state files (reconciliation) | yes |
| `data/raw/population/` | PEP county totals, every vintage ingested | yes |
| `data/geography/` | Cartographic boundary zips | yes |
| `data/raw/manifest.json` | Provenance per file: agency, URL, survey period, server listing time, HTTP Last-Modified, download time, SHA-256, byte size, prior versions; plus files unavailable at source | yes |
| `data/releases/index.json` | Every published dataset version | yes |
| `data/releases/<version>/` | Snapshot: current TTM and calendar-year tables (CSV) and the release record with its validation report | yes |
| `data/logs/refresh-log.jsonl` | One line per refresh attempt that changed data | yes |
| `data/processed/` | Parquet tables (below), regenerated by every build | no |
| `public/data/` | Web artifacts (below), regenerated by every build | no |

Version id: `<data month>.<first 8 hex chars of SHA-256 over all input file hashes and the processing version>`,
e.g. `2026-08.a711eff5`. The same inputs always produce the same id and byte-identical artifacts.

## Processed tables (`data/processed/*.parquet`)

**`county_ttm_current.parquet`**: one row per county equivalent (3,144).

| Column | Meaning |
|---|---|
| `geoid` | 5-digit county FIPS |
| `name`, `st` | County name (`NAMELSAD`) and state abbreviation |
| `class` | `complete`, `current_only`, `incomplete`, `annual_only`, `not_in_bps` |
| `period_start`, `period_end` | Current TTM window (YYYY-MM) |
| `ttm_total`, `ttm_u1`, `ttm_mf`, `ttm_u2`, `ttm_u34`, `ttm_u5` | Current TTM housing units: total, single-family, multifamily (2+), 2-unit, 3–4-unit, 5+-unit buildings |
| `prior_ttm_*` | Same for the prior window |
| `yoy_pct`, `yoy_sf_pct` | Growth %, total and single-family (NaN = undefined or N/A) |
| `per_1000`, `per_1000_sf` | Units per 1,000 residents |
| `population` | PEP July 1 estimate for the vintage's latest year |
| `imputed_share` | 1 − reported-only TTM / estimated TTM |
| `flags` | `;`-separated: `low_baseline`, `low_baseline_sf`, `no_prior_permits`, `high_imputation`, `revision_adjustment`, `revision_inconsistency`, `monthly_annual_divergence`, `small_population` |

**`county_annual_current.parquet`**: calendar-year view (`cy_*`, `prior_cy_*`, `yoy_pct`, `per_1000`, `population`, `year`).

**`county_monthly_history.parquet`**: `geoid`, `period`, `month_sf`, `month_mf` (first-published monthly units), `ttm_total`, `ttm_sf`, `yoy_pct`, `ttm_full_coverage`.

**`county_annual_history.parquet`**: final annual units by type, 2000–latest.

**`population_v<vintage>.parquet`**: `geoid`, `year`, `population`, `vintage`, `source`.

## Web artifacts (`public/data/`)

| File | Contents |
|---|---|
| `meta.json` | Version, reporting periods, population and geography vintages, coverage statistics, thresholds, source files with hashes, Census notices, legacy codes, validation report, release history |
| `metrics.json` | Columnar metrics for all 3,144 counties, both views (`ttm`, `annual`); ranks as `[national rank, n, state rank, n]` (0 = not ranked); `recon` = monthly December YTD vs annual |
| `history/<state fips>.json` | Per county: `m_sf`, `m_mf` (monthly, first published), `t_all`, `t_sf` (TTM), `y_all`, `y_sf` (YoY %), all from `meta.history.start`; `a_sf`, `a_mf` (annual, from `meta.history.annual_start`). `null` = absent from the source file |
| `geo/counties.geojson`, `geo/states.geojson`, `geo/insets.geojson` | Display geometry (composite projection; see methodology) |
| `geo/index.json` | Names, state, bounding boxes |
| `validation.json` | Full validation report |

No county value is hard-coded in application source. Everything the site shows comes from these files.
